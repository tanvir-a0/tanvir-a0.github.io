Video Hosting Methods for GitHub Pages

Method 1: Direct Repository Hosting

Pros:

  • Simple - just commit video files to repo
  • Works immediately with GitHub Pages
  • Full control over video files

Cons:

  • File size limit: ~100MB per file (GitHub recommendation)
  • Repository size limit: 5GB recommended, 100GB hard limit
  • Slower load times for large videos
  • Uses repository storage quota

Best For:

Small videos (<50MB), demos, short clips, GIF alternatives

Method 2: GitHub Releases

Pros:

  • Files up to 2GB supported
  • Doesn't count toward repository size
  • Permanent CDN-backed URLs
  • Version control for video files

Cons:

  • Requires creating a release
  • Extra steps to update videos
  • Not as straightforward as direct hosting

Best For:

Larger videos (50MB-2GB), production videos, downloadable content

How to Use:

  1. Go to your GitHub repo → Releases → Create new release
  2. Upload video as release asset
  3. Copy the asset URL (right-click on the file link)
  4. Use that URL in your video src

  <source src="https://github.com/username/repo/releases/download/v1.0/video.mp4">
</video>

Method 3: Git Large File Storage (LFS)

Pros:

  • Handles large files efficiently
  • Version control for large files
  • 1GB free storage, 1GB free bandwidth/month
  • Keeps repository clone fast

Cons:

  • Requires Git LFS setup
  • Limited free bandwidth (1GB/month)
  • Additional costs beyond free tier ($5/50GB)
  • Collaborators need Git LFS installed

Best For:

Teams with large media files, projects with many video versions

Setup:

  1. Install Git LFS: git lfs install
  2. Track video files: git lfs track "*.mp4"
  3. Commit .gitattributes file
  4. Add and commit videos normally

Files tracked by Git LFS work the same way in HTML

Method 4: External Hosting (YouTube, Vimeo, etc.)

Pros:

  • Unlimited storage and bandwidth
  • Professional video player with features
  • Automatic transcoding and quality options
  • SEO benefits and discoverability
  • Analytics and view tracking

Cons:

  • Requires external account
  • Videos may be public (or need paid Vimeo)
  • Branding from hosting service
  • Less control over player appearance

Best For:

Large videos, public content, tutorials, marketing videos

Method 5: Optimized HTML5 Video (Best Practice)

Optimization Tips:

  • Compress videos (H.264 codec, MP4 container)
  • Provide multiple formats (MP4, WebM) for browser compatibility
  • Use preload="metadata" for faster page load
  • Add poster image for better UX
  • Implement lazy loading for multiple videos
  • Consider adaptive streaming for long videos

Recommended Tools:

  • HandBrake: Free video compression
  • FFmpeg: Command-line video processing
  • CloudConvert: Online video conversion

📋 Quick Recommendations

Small Videos (<25MB)

Use Method 1: Direct repository hosting

Simple, works out of the box

Medium Videos (25-100MB)

Use Method 2: GitHub Releases

Better performance, doesn't bloat repo

Large Videos (>100MB)

Use Method 4: External hosting (YouTube/Vimeo)

Free, unlimited bandwidth, professional features

Professional Projects

Use Method 4 or Method 3 with optimization

Best quality and user experience

🎬 Video Compression Commands (FFmpeg)

Basic Compression (Recommended):

ffmpeg -i input.mp4 -c:v libx264 -crf 23 -preset medium -c:a aac -b:a 128k output.mp4

High Compression (Smaller file):

ffmpeg -i input.mp4 -c:v libx264 -crf 28 -preset slow -c:a aac -b:a 96k output.mp4

WebM Format (Modern browsers):

ffmpeg -i input.mp4 -c:v libvpx-vp9 -crf 30 -b:v 0 -c:a libopus output.webm

Create Poster Image:

ffmpeg -i input.mp4 -ss 00:00:05 -vframes 1 poster.jpg
